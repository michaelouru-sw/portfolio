Course Audit Tool — Uniqualified

KCA University / Open-Source · 2026 · PHP / Moodle / MySQL

View Repository

The Problem

KCA University's Quality Assurance office was manually cross-referencing timetable spreadsheets against Moodle courses every term — checking whether each course had the right activities, the right lecturer, and evidence the term had started. The process was slow, error-prone, and entirely manual. Worse, there was no mechanism to see a problem developing before it became serious: issues only surfaced after a student or accreditation body complained.

Target Audience

QA officers and programme coordinators running periodic course audits across a multi-faculty, multi-campus Moodle deployment — plus university leadership needing trend-level visibility into course quality over time.

My Role

Sole developer — end-to-end: architecture, backend, database design, algorithm design (including the Bayesian adaptive weighting and Mann-Kendall trend engine), Moodle API integration, testing, and documentation — verified against a live Moodle 5.0.8 instance with real data.

Design Process & Approach

I started from the real QA workflow — not an abstraction of it — and identified three failure modes the spreadsheet approach couldn't fix: it couldn't scale, it couldn't catch trends, and it couldn't learn which quality signals actually mattered for this institution. The design process moved from that problem statement outward: data model first, then reconciliation logic, then the risk engine, then the dashboard, then admin configurability. Every layer was verified on live data before the next was built.

The Solution

A production-grade Moodle plugin (local_courseaudit) with five integrated capabilities:

  • Multi-format timetable reconciliation — parses real institutional spreadsheets across multiple inconsistent faculty formats and matches each row against live Moodle course data, including disambiguation logic for unit codes that map to several offerings.
  • Configurable compliance-audit dashboard — filterable, paginated view of every course's compliance against a quality template, with bulk review actions, category-scoped access for programme coordinators, and one-click Excel export including multi-tab mismatch and anomaly reports.
  • Real Moodle Analytics (ML) integration — surfaces Moodle's native course-risk and student-dropout predictions directly on the dashboard; includes a dedicated ML Insights page and the ability to message at-risk students or bulk-email at-risk course lecturers via Moodle's real messaging and notification APIs.
  • Adaptive risk-scoring engine — a composite 0–100 score fusing five signal types. Two signals use Beta-Bernoulli conjugate updating (a Bayesian online-learning technique) so each signal's weight is continuously re-estimated from whether its past flags actually held up. A signal that reliably predicts lasting problems earns more weight; one that flags things that self-resolve earns less — automatically, from this institution's own data.
  • Statistical early-warning trend detection — records a timestamped quality snapshot every run (optionally via a daily background task) and applies a Mann-Kendall nonparametric trend test to flag a course that's meaningfully declining before any single rule fires. Verified on a real course showing 100% → 71% → 14% → 0% compliance across four snapshots.

All 23 originally hardcoded parameters — quiz naming conventions, brand colours, timetable column headers, thresholds — are now admin settings, so a different institution can adopt the plugin without touching code.

Results & Impact

Manual QA replaced end-to-end
Self-learning risk weights
Early-warning before threshold breach
Institution-agnostic (23 config settings)

Technical Competencies Demonstrated

  • Moodle 5.0 plugin architecture (PHP, hooks, capabilities, events)
  • Bayesian online learning — Beta-Bernoulli conjugate updating
  • Mann-Kendall nonparametric trend test (implemented from first principles)
  • Moodle Analytics API integration (ML predictions surfaced in UI)
  • Multi-format spreadsheet parsing and timetable reconciliation
  • Excel export with multi-tab anomaly reporting
  • End-to-end unit testing against a live Moodle instance
