Moodle Machine Learning Backend

KCA University · 2026 · Python / Moodle Analytics API / AWS

View Live LMS

The Problem

Moodle's native Analytics API can predict student dropout and course risk - but only when a Python ML backend is running reliably behind it. In practice this backend is notoriously difficult to configure, and KCA University's deployment had it either missing or non-functional. As a result, 10,000+ distributed users had no access to Moodle's predictive intelligence: the Insights page was empty, dropout flags never fired, and course-risk predictions were silent.

Target Audience

University QA officers, programme coordinators, and academic managers needing early-warning signals on at-risk students and underperforming courses - across KCA University's multi-campus Moodle deployment serving 10,000+ active users.

My Role

Lead engineer - diagnosed the missing ML backend, engineered and configured the Python environment, integrated it with Moodle's Analytics API, and deployed to production on AWS. Also surfaced the resulting predictions inside the Course Audit Tool dashboard, making insights actionable rather than buried in Moodle's native Insights page.

Design Process & Approach

The first challenge was diagnosis - Moodle's Analytics API fails silently when its ML backend is absent or misconfigured, so establishing a clear picture of what was missing required tracing the API call chain, inspecting server logs, and cross-referencing Moodle's documentation against the actual Python environment state. Once the gap was identified, the work was methodical: provision the correct Python environment on AWS, configure Moodle's analytics settings to point to it, validate predictions were generating, then surface those predictions where QA staff would actually see and act on them - integrated into the Course Audit Tool dashboard, not left on a page most users never visit.

The Solution

A fully operational Moodle Analytics ML backend deployed on AWS, with predictions surfaced directly inside the Course Audit Tool:

  • Python ML backend provisioning - engineered the correct Python environment, dependencies, and Moodle configuration to enable the Analytics API's machine learning models on a production server.
  • Dropout and course-risk prediction activation - Moodle's built-in predictive models (student dropout likelihood, course-at-risk flags) now run on schedule and generate real insights from live enrolment and activity data.
  • Dashboard integration - ML predictions are surfaced directly on the Course Audit Tool's compliance dashboard and a dedicated ML Insights page, listing every flagged student or course by name.
  • Actionable messaging - QA staff can message an at-risk student directly or bulk-email the lecturers of at-risk courses from within the dashboard, using Moodle's real notification and email APIs - no manual lookup required.
  • Production deployment on AWS - configured for reliability and compatibility with KCA University's existing Moodle 5.0.8 infrastructure.

Results & Impact

10,000+ users served
Live dropout prediction enabled
Course-risk flags active
Production-deployed on AWS

Technical Competencies Demonstrated

  • Python ML environment provisioning and dependency management
  • AWS server configuration for Moodle production deployments
  • Moodle messaging and notification API integration
  • Silent-failure diagnosis in complex multi-component systems
  • Bridging ML infrastructure and end-user UX (predictions → actionable dashboard)
